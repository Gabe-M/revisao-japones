### Code Inspection Findings (`api/dialogo.js`)

#### Finding A: Line 1492 - Whitespace `exemplo_pt` Fallback Shadowing Defect
```js
1457: const precisaTraduzirExemplo = body.exemplo_jp && (!body.exemplo_pt || !body.exemplo_pt.trim());
...
1492: exemplo_pt: body.exemplo_pt || result.exemplo_pt || null
```
- Line 1457 correctly evaluates `!body.exemplo_pt.trim()` to `true` when `body.exemplo_pt` is a whitespace-only string (e.g. `"   "`), which triggers the AI prompt instruction to translate `body.exemplo_jp`.
- However, line 1492 constructs the returned `cardEnriquecido` using `exemplo_pt: body.exemplo_pt || result.exemplo_pt || null`.
- In JavaScript, any non-empty string (including `"   "`) is truthy (`Boolean("   ") === true`).
- Therefore, `"   " || result.exemplo_pt` evaluates to `"   "`. The AI translation generated by the LLM (`result.exemplo_pt`) is completely ignored and overwritten by `"   "`.

#### Finding B: Line 1457 - Unhandled `TypeError` for Non-String `exemplo_pt`
```js
1457: const precisaTraduzirExemplo = body.exemplo_jp && (!body.exemplo_pt || !body.exemplo_pt.trim());
```
- If `body.exemplo_jp` is provided and `body.exemplo_pt` is a non-string truthy value (e.g. `true` or `123`), `!body.exemplo_pt` is `false`.
- JavaScript proceeds to evaluate `!body.exemplo_pt.trim()`.
- Because `(true).trim` is `undefined`, invoking `(true).trim()` throws an unhandled **`TypeError: body.exemplo_pt.trim is not a function`**.
- This unhandled exception crashes the endpoint logic and bubbles up to the outer catch block, returning a 500 error instead of handling input gracefully.

#### Finding C: Verified Handled Behaviors
1. **Whitespace-only item input**:
   - Lines 1415–1417:
     ```js
     const palavra = body.item || body.palavra || body.termo;
     if (!palavra || typeof palavra !== 'string' || !palavra.trim()) {
         return res.status(400).json({ error: 'Palavra ou item não informado para enriquecimento.' });
     }
     ```
   - Retaining `400 Bad Request` with message `'Palavra ou item não informado para enriquecimento.'`.
2. **Undefined optional fields**:
   - `leitura`, `categoria`, `jlpt`, `exemplo_jp`, `exemplo_pt` default safely to empty strings or `null`.
3. **Empty `exemplo_jp`**:
   - If `body.exemplo_jp` is empty string `""` or `null`, `precisaTraduzirExemplo` is falsy, example prompt is omitted, and `cardEnriquecido.exemplo_jp` returns `null`.
4. **Null `exemplo_pt`**:
   - If `body.exemplo_pt` is `null` (or omitted) with a valid `body.exemplo_jp`, `precisaTraduzirExemplo` evaluates to `true`, LLM generates `exemplo_pt`, and line 1492 returns `result.exemplo_pt`.
5. **Network Timeout Handling**:

## 4. Conclusion

**Final Assessment**: **FAIL**

While standard boundary inputs (whitespace `item`, missing fields, null `exemplo_pt`, empty `exemplo_jp`, and Jisho timeouts) are properly handled, `case 'enriquecer_card'` contains two bugs:
1. **Whitespace Shadowing Defect**: Line 1492 evaluates `body.exemplo_pt || result.exemplo_pt || null`. When `body.exemplo_pt` is whitespace (e.g. `"   "`), line 1492 returns `"   "` instead of using the AI-generated `result.exemplo_pt`.
2. **Missing Type Guard**: Line 1457 calls `.trim()` without verifying `typeof body.exemplo_pt === 'string'`, throwing a `TypeError` if `exemplo_pt` is non-string truthy.

### Actionable Remediation
In `api/dialogo.js`:
- Update line 1457:
  ```js
  const temExemploPtValido = typeof body.exemplo_pt === 'string' && body.exemplo_pt.trim().length > 0;
  const precisaTraduzirExemplo = body.exemplo_jp && !temExemploPtValido;
  ```
- Update line 1492:
  ```js
  exemplo_pt: temExemploPtValido ? body.exemplo_pt : (result.exemplo_pt || null)
  ```
